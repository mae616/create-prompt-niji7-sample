# create-prompt

niji journey 用プロンプトを生成するスキル。

## トリガー
- ユーザーが `/create-prompt` を実行したとき
- ユーザーが「プロンプトを作って」「prompt生成」等を依頼したとき

## 説明
入力情報から niji journey 向けの画像生成プロンプトを、ドメインカプセルの知識を合成して生成する。
ドメインごとにカプセル化された指示を、矛盾なく合成するのが特徴。

## 入力
- `prompts/input.md` の内容
- または、スキル実行時の引数テキスト

## 実行手順

### 1. 入力の読み取り
- `prompts/input.md` を読む
- 引数がある場合はそちらを優先

### 1.5 キャラクター設定の参照
- 入力テキストに含まれる名前が `characters/` 配下のMDファイル名と一致するか確認する
- ファイルが見つかった場合、そのキャラクターの外見設定を入力に統合する
- 入力で明示的に上書きされた項目は、そちらを優先する
- ファイルが見つからない場合はスキップする
- `_template.md` は除外

### 1.6 スタイルプリセットの参照
- 入力テキストに含まれる名前が `styles/` 配下のMDファイル名と一致するか確認する
- ファイルが見つかった場合、その設定を合成に統合する
- スタイルが上書き対象とするカプセルのルールと矛盾する場合、スタイル側を優先する
- ファイルが見つからない場合はスキップする

### 2. ドメインカプセルの読み込み
- `.claude/skills/create-prompt/domains/` 配下の全 `.md` ファイルを読む
- `_template.md` は除外
- 各カプセルの `priority`（優先度）と `conflicts`（競合ルール）を確認

### 3. プロンプト合成

#### カプセル一覧（priority順）
| priority | カプセル | 役割 |
|----------|---------|------|
| 10 | output-rules.md | 合成の優先順位・全体方針・プロンプト形式 |
| 9 | face-expression.md | 顔・表情・目元構造 |
| 8 | art-style.md | 画風・線質・色面構造 |
| 8 | character-form.md | キャラクター造形・絵柄ポジション |
| 7 | coloring.md | 色彩・配色・影色 |
| 7 | painterly-texture.md | 絵画的質感・画材・技法 |
| 5 | composition.md | 情報密度・視線誘導・空間設計 |
| 4 | character.md | キャラクター外観基礎（素材情報） |
| 3 | world-setting.md | 世界観・環境基礎 |

#### プロンプト構築順序
```
1.主役物理定義 → 2.焦点物体 → 3.髪 → 4.目 → 5.肌 → 6.衣装層
→ 7.ポーズ+カメラ → 8.光 → 9.画材 → 10.技法 → 11.色面構造 → 12.影色混合
→ 13.背景 → 14.密度差 → 15.線の役割 → 16.禁止要素
```

#### 合成ルール
- output-rules.md の優先順位（画風成立 ＞ 主役視認性 ＞ 配色成立 ＞ 構造維持 ＞ 情報再現）を常に守る
- `conflicts` で定義された競合がある場合、`priority` が高いカプセルを優先する
- 入力で明示的に指定されたものは、カプセルのデフォルトを上書きする
- 曖昧な雰囲気語・ジャンルラベルは使わず、視覚的に解釈可能な要素へ分解する

### 4. 履歴ファイル作成
`prompts/history/YYYY-MM-DD_HHmm_{title}.md` を新規作成する。
- `{title}` は入力情報から短いタイトルを自動生成
- ステータスは「作業中」で開始

### 5. 出力と記録
- 生成プロンプトは画面に表示し、同時に履歴ファイルに追記する
- 初回は v1 として記録
- 修正のたびに v2, v3... と追記する（修正指示もそのまま残す）

### 6. 継続対話
生成後、以下を提示する：
```
プロンプトを生成したにゃ。
履歴: prompts/history/{ファイル名}.md

次にできること：
1. 「修正して」「〜を強調して」→ 修正版を生成（vN+1として記録）
2. 「バリエーション」→ 同じ入力で異なるアプローチを生成
3. 「完成」→ ステータスを「完成」に変更
4. 「新規」→ 新しい履歴ファイルで開始
```

## 出力フォーマット
- niji journey の `/imagine prompt:` 形式に準拠
- 英語プロンプトが主、日本語訳は参照・確認用

## 品質チェック（生成後セルフレビュー）

出力する前に以下を確認し、不合格なら自動修正してから出力する。

### A. カプセル準拠
- 概念語が単体で使われていないか（必ず `defined as` / `visually interpreted as` 付き）
- 禁止ブロック4文が末尾に含まれているか
- 画材が `[medium], visually interpreted as [physical behavior]` 形式か
- 技法が `[technique], defined as [visual construction behavior]` 形式か

### B. 画面成立（優先順位順）
- 画風成立：塗り方・線の扱い・描画密度が明示されているか
- 主役視認性：主役が1つに寄っているか
- 配色成立：無彩色のみ／白背景になっていないか
- 構造維持：空間タイプと光条件が指定されているか

### C. 禁止事項
- photo / realistic / photorealistic / 3D render が含まれていないか
- pure black / heavy outline が使われていないか
- ジャンルラベル（moe, kemonomimi, chibi 等）が単体で使われていないか

### D. フレーズ構造
- 1フレーズ＝1視覚意図になっているか
- フレーズ順が `output-rules.md` に沿っているか
- 意味衝突するフレーズが隣接していないか
